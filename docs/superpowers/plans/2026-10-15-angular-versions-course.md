# Angular Versions Course (14 → 16 → 18 → 20 → 22) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a self-paced Angular modernization course (5 workspaces, 7 lessons, ~14 offline diagrams, test-driven exercises, `solutions` branch) cloning the structure of `../java-cheat-sheet`.

**Architecture:** Five fully independent Angular workspaces (`ng14`…`ng22`), each with a complete TaskBoard sample app (idiomatic for its major) plus failing exercise stubs with behavioral tests. Markdown lessons render offline via a generated `lessons-data.js`; standalone HTML diagrams are indexed by `index.html`. `tools/run.mjs` orchestrates per-version test runs through nvm.

**Tech Stack:** Angular 14/16/18 (Karma+Jasmine), Angular 20/22 (Vitest), TypeScript per Angular major, Node 16/18/20/22/24 via nvm-windows, plain Node ESM tools, archify for diagrams.

**Spec:** `docs/superpowers/specs/2026-10-15-angular-versions-course-design.md`

## Global Constraints

- Workspaces: exactly `ng14`, `ng16`, `ng18`, `ng20`, `ng22` at repo root; no root `package.json`; each workspace has its own lockfile and `node_modules`.
- Node per workspace (nvm-windows): `ng14`→16, `ng16`→18, `ng18`→20, `ng20`→22, `ng22`→24. Machine default restored to Node 24 after every orchestrated run.
- Test runners: Karma+Jasmine (`ng14`–`ng18`), Vitest (`ng20`–`ng22`; fallback Karma only if Vitest proves unusable in 20 — spec risk note).
- Exercise stubs and specs live under `src/app/exercises/**`; the reference app lives under `src/app/taskboard/**`. Test file names and exercise paths are identical in all workspaces that contain them (`ng16`–`ng22`; `ng14` has NO `exercises/` — its TaskBoard is the implemented baseline, mirroring `java08`).
- Every exercise stub compiles but fails its specs with a visible `TODO Angular NN` error.
- `lessons/*.md` is the source of truth; `lessons-data.js` is generated by `tools/build-lessons.mjs` and committed together with lesson edits.
- All HTML artifacts (`index.html`, `lessons.html`, `diagrams/**`) must work via `file://` — no fetch/XHR/ES-module imports from disk; scripts loaded with `<script src>`.
- Feature-to-version assignments must be verified against official release notes (angular.dev changelog / blog) during each workspace task; correct the lesson/matrix content if a pinned fact is wrong, and note the fix in the task report.
- Git: branch `main` (stubs + full TaskBoard); branch `solutions` (completed exercises). Simple imperative commit messages.

## Version idioms (binding for TaskBoard ports and solutions)

| Concern | ng14 | ng16 | ng18 | ng20 | ng22 |
|---|---|---|---|---|---|
| Bootstrapping | NgModules (`AppModule`) | standalone `bootstrapApplication` | standalone | standalone | standalone |
| Components | decorator `@Input/@Output`, NgModule declarations | `standalone: true` | standalone | + `input()/output()` in exercises where applicable | OnPush default (strategy `Eager` before v22 rename — set explicitly) |
| Templates | `*ngIf/*ngFor` | `*ngIf` + `trackBy` | `@if/@for/@defer/@let` | `@if/@for` | + template arrow fns, spread (use where natural) |
| State | plain fields/getters | `signal()/computed()` (preview) | signals | + `linkedSignal` where natural | + async reactivity where natural |
| DI | constructor injection | `inject()` | `inject()` | `inject()` | `inject()` |
| Forms | typed reactive forms | typed reactive | reactive + control events | reactive + events API | Signal Forms |
| Guards | class `CanActivate` | functional `CanActivateFn` | functional | functional | functional |
| Tests | Karma/Jasmine | Karma/Jasmine | Karma/Jasmine | Vitest | Vitest |
| Node | 16 | 18 | 20 | 22 | 24 |

export interface Task { id: number; title: string; status: TaskStatus; }

- Every stub file starts with `// TODO Angular NN — see lessons/NN-<slug>.md` and throws / returns placeholder so the suite compiles and fails.
- Spec files are colocated (`*.spec.ts`), same names in every module; assertions are behavioral (TestBed + DOM / service calls) and identical across modules — only imports differ where the idiom table requires (e.g., functional guard vs. nothing in v14).
- Version scope per lesson stub: `ng16` contains all 12 files; `ng18`/`ng20`/`ng22` identical paths. (Lesson content decides which stubs a learner touches per version; all remain present so tests stay verbatim.)

## Review Focus

1. **nvm-windows global switch must always restore Node 24** — even when tests fail. Test: task 2 failure-path dry-run/forced-fail step asserts restore command emitted.
2. **Karma needs a browser binary on Windows** — `ng14`–`ng18` must run headless. Test: task 3 sets `CHROME_BIN` fallback to Edge (`msedge.exe`) and runs the suite headless successfully.
3. **Vitest + zoneless TestBed (v20/v22)** — signal-based TaskBoard may run zoneless; fixtures must boot. Test: tasks 8/10 smoke spec passes under `ng test` (Vitest).
4. **Template syntax must respect the version floor** — no `@if` in ng16 TaskBoard, no `*ngIf` in ng22 TaskBoard. Test: tasks 4/6/8/10 include a grep step over `taskboard/**/*.html` asserting only the allowed structural syntax for that version.
5. **Generated viewer link integrity** — `lessons-data.js` code links and `index.html` anchors must match real files/ids. Test: task 1 build validates `LESSON_CODE` paths exist; task 20 checks every `lessons.html#…` href in `index.html` against lesson slugs.
